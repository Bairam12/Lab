# ЛР №12 — Вариант 18: OIDC-вход через sandbox-провайдера (authorization code + PKCE)

Стек: Node.js 20.12+ (нужен для `process.loadEnvFile`; без `.env` подойдёт и 18+), библиотека `openid-client` v6.

## Как запустить
1. Один раз установите Node.js (версия LTS): https://nodejs.org — обычная установка, «Next» до конца.
2. Дважды щёлкните по файлу **`start.bat`** в этой папке. Откроется чёрное окно сервера и браузер с адресом **http://localhost:3018**. При первом запуске батник сам выполнит `npm install` (нужен интернет).
3. Работайте в браузере. Чёрное окно не закрывайте — пока оно открыто, сервер работает. Чтобы остановить сервер, закройте окно.

Автотесты: в папке проекта выполните `npm test` (для варианта 18 — офлайн-проверки защиты и сессий).

Нельзя открывать `public/index.html` двойным кликом или через Live Server: вход выполняет сервер на Node.js.
Если браузер не открылся сам, откройте адрес вручную. Если пишет, что порт занят, — сервер уже запущен в другом окне.

## Провайдер
По умолчанию используется публичный тестовый провайдер `https://op.panva.hu` (динамическая регистрация клиента; на его странице входа можно ввести любое имя, реальные данные не нужны). Для другого провайдера (Google, Auth0, Keycloak) скопируйте `.env.example` в `.env` и заполните `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`. Файл `.env` в репозиторий не коммитить (он в `.gitignore`). Вход работает только при наличии интернета.

## Поток входа
1. `GET /auth/login` — сервер создаёт `code_verifier` (PKCE), `code_challenge = S256(verifier)`, `state`, `nonce`; сохраняет их на сервере (cookie `tx` хранит только случайный id попытки) и перенаправляет на провайдера.
2. Пользователь входит **у провайдера** — приложение не видит пароль.
3. `GET /auth/callback?code=…&state=…` — сервер сверяет `state`, обменивает `code` + `code_verifier` на токены; библиотека проверяет подпись ID-токена, `iss`, `aud`, `exp`, `nonce`.
4. Из ID-токена берутся claims (`sub`, `name`, `email`), создаётся серверная сессия, выдаётся cookie `sid` (HttpOnly, SameSite=Lax). Токены в браузер не передаются.
5. `GET /api/profile` — защищённый ресурс (401 без сессии). `POST /auth/logout` — уничтожает сессию.

Обработка callback: отказ провайдера (`error=`), устаревшая или повторная попытка, неверный `state`/`nonce`, недоступный провайдер — пользователь возвращается на главную с понятным сообщением.

## Творческое задание
Диалог подтверждения выхода и индикатор оставшегося времени сессии.

## Важно
Свой OAuth-сервер здесь не реализуется (требование методички) — используется внешний провайдер и готовая библиотека. Офлайн-тесты не проверяют обмен с провайдером: этот шаг нужно показать вручную в браузере и сделать скриншоты.
