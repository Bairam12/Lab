# Вариант 18 — OIDC-вход (authorization code + PKCE), локальная имитация провайдера
Откройте `index.html` двойным кликом. Логин на странице провайдера: `student` / `Test-Pass-123`.

**Файлы:** `index.html` + `app.js` (приложение, Relying Party), `provider.html` + `provider.js` + `idp-core.js` (имитация провайдера: авторизация, выдача кода, обмен на токены, ключи), `crypto-utils.js`.

## Поток
1. «Войти через OIDC»: приложение создаёт `code_verifier`, `code_challenge = BASE64URL(SHA-256(verifier))`, `state`, `nonce` и переходит на `provider.html`.
2. Провайдер проверяет параметры (client_id, redirect_uri, scope openid, PKCE S256), принимает логин/пароль и показывает экран согласия. Пароль видит только он.
3. Возврат в `index.html?code=…&state=…`: приложение сверяет `state`, «обменивает» код на токен (провайдер сверяет `code_verifier` с `code_challenge`; код одноразовый, срок 60 с).
4. Приложение проверяет ID-токен: алгоритм и подпись RS256 по открытому ключу провайдера, `iss`, `aud`, `exp`, `nonce`. Создаётся сессия (хранятся только claims, сам токен не сохраняется).
5. `/profile` — защищённый ресурс (401 без сессии). Выход — с диалогом подтверждения.

**Обработка ошибок:** отказ пользователя (`access_denied`), подмена `state`, неверный `code_verifier`, повторное использование кода, истёкшая сессия — понятные сообщения. Кнопки на панели проверки воспроизводят подмену `state` и неверный `code_verifier`.
**Творческое задание:** подтверждение выхода и индикатор времени сессии.

## Ограничение (обязательно укажите в отчёте)
Это **локальная имитация** OIDC без реального провайдера и без официальной библиотеки: методичка допускает такой вариант при явной пометке. Для входа через реальный sandbox-провайдер с библиотекой используйте Node.js-версию из архива `lab12-individual-tasks.zip`.
