## Важно для отчёта (пишите это честно)
Это **учебные прототипы с эмуляцией сервера**: роль серверного обработчика играет JavaScript-файл (`server-sim.js` / `idp-core.js`), данные лежат в localStorage браузера. Методичка это допускает, если явно указать в отчёте: «выполнен интерфейсный прототип с эмуляцией серверной части». Настоящей защиты такой прототип не даёт.
Логика при этом настоящая: сессии со сроком жизни, хеширование паролей (PBKDF2), коды ответов 200/400/401/403/404/429, проверка прав и владельца ресурса «на стороне сервера», а в варианте 18 — настоящие PKCE (SHA-256), подпись ID-токена RS256 и проверка state / nonce / iss / aud / exp.
Если преподаватель требует реальный сервер и официальную библиотеку OIDC (п. 8 методички), используйте архив `lab12-individual-tasks.zip` (Node.js).
